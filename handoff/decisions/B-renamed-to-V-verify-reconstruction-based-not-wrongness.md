# B (wrongness) is RENAMED to V (Verify) — reconstruction-based, not wrongness-detection [USER; new name [me]-proposed]

**Decision (USER):** rename "B", the middle of the C→B→A loop. It is no longer "detect WRONG info."

**New name — [me]-proposed, CONFIRM or override:** **V — Verify.** The loop becomes **C (self-assemble) → V (verify /
understand) → A (edit)**. (Alternatives if you prefer: "Understand", "Reconstruct".)

**What V is:** verification by **RECONSTRUCTION** — reverse-embed the representation and COMPARE to the original /
expectation ("can I regenerate this from my understanding?"). NOT by surprise, NOT by self-consistency-on-surprise.

**Why the reframe:** the old B tried to read TRUTH off SURPRISE — a category error (surprise drives LEARNING, not truth;
see `surprise-is-a-learning-driver-not-a-wrongness-or-truth-signal.md`). That conflation is why B sat at ~1% precision for
the entire project. V replaces the signal with a real one, decoupled from surprise (see
`../design-directions/reverse-embedders-for-thought-verification-and-training.md`).

**Scope of the rename:** applied going-forward in the LIVING docs (STATE.md, GLOSSARY, README, CL_TESTBED, this folder).
HISTORICAL / FROZEN records keep "B" as written (`garry/`, `handoff/history/`, the STATE changelog) — read any residual
"B" there as "V (formerly B)". The old broken self-consistency `is_wrong` / `selfcheck` CODE keeps its names until the build replaces it.

**Supersedes:** the old open question "corroboration-B vs cut-B" (Q3) — the answer is NEITHER: replace with V (reconstruction).
