# Interchangeable base + EMERGENT subspecialties — the target for the expert society [USER direction]

Resolves the redundancy-vs-modularity tension (`../open-questions/Q-regime...`) as BOTH, compositionally — NOT a binary pick.

**What the user wants:**
- INTERCHANGEABILITY / redundancy is valued for two concrete reasons:
  1. **Safety against INCORRECT removal** — if experts are redundant, a wrong deletion doesn't cost a capability.
  2. **Many tasks, broken down, share SIMILAR sub-tasks** — shared interchangeable units give reuse + flexibility.
- On top of that, **SUBSPECIALTIES should EMERGE for specific tasks, by breaking tasks down** — specialization is a
  bottom-up, compositional OUTCOME, not an imposed partition.

**So the target is a hierarchy/composition:** a redundant, interchangeable general base + emergent specialists for
specific tasks. Both at once.

**The design challenge (OPEN):** the current INDEPENDENCE LOSS produces redundancy by training every expert to solve the
whole task ALONE — which actively PREVENTS specialization. Getting emergent subspecialties WITHOUT losing the redundant
safety net is the real problem. Candidate levers (none decided): hierarchical / compositional routing; letting
specialization emerge via the evolution & selection scheme (`../open-questions/Q0...`); a redundant CORE plus
specialization at the margins; task-decomposition-driven expert birth.

**Status:** direction, not a mechanism. Refines Q-regime and Q0 (they are really one question — see `../NORTH_STAR.md`).
