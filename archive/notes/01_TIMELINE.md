# 01 — TIMELINE

> Nothing in this project has been optimised. Strategy is still being built. Sample sizes are tiny
> — usually n=1, occasionally n=3 — and the measured seed spread on a single arm has reached
> 1.227 b/B (`33a9299`), larger than the gap between any two architectures ever compared here.
> Several confidently-stated findings were later retracted when the measurement turned out to be
> broken. Every entry records **what was observed under these conditions**, never **what is true**.
> Where a result was later invalidated, the invalidation is stated next to it, not in a footnote.

---

## What this file is

The dated spine. One row per commit that changed **what was being measured** — either by changing
the system under measurement, or by changing the instrument measuring it. Every other file in
`notes/` cites this one by short hash.

**Source.** `notes/_evidence/commit_log.txt` (267 commits on `rm-predict`, `8150f8a` 2026-07-21 →
`92a967b` 2026-08-15), read start to finish. Ancestry claims were verified with
`git merge-base --is-ancestor`. Where a row states a number, that number is quoted from the commit
message that produced it; nothing here is recomputed or inferred.

**Reading the columns.**

- **SYSTEM** — what the running system does differently after this commit.
- **MEASUREMENT** — what the *instrument* now reports, or reports differently. **This is the column
  that matters.** A change here means numbers taken before it and after it are not the same
  quantity, whatever the system was doing. Rows where SYSTEM is `—` are pure instrument changes,
  and those are the ones that invalidate earlier results.

**Rules this file follows.**

1. No row without a commit hash.
2. No claim stated as true. Every number carries the conditions it was taken under, and `n` where
   the commit stated one. Where the commit did not state `n`, this file says so rather than guessing.
3. Where a commit retracted an earlier claim, the retraction sits in the row, not in a footnote.
4. HEAD at time of writing is `92a967b` (2026-08-15). `DOC_PLAN.md` was written against `a5cc7ea`
   and describes 259 commits; eight commits landed after it, and they are included here.

## Appendix B — corpus lineage, and what `held_out` is comparable to

**Was the corpus re-fetched between the 8-epoch arms and `ep18_big`? Yes.** `ac79e92` states it
directly: *"the corpus was re-fetched larger for this run and got HARDER (order-1 3.440 → 3.747), so
the raw held-out is not comparable to the 8-epoch arm B."* Against each run's own order-1 anchor the
two are 1.411 vs 1.441.

`runs.csv` carries no corpus column, but it carries `uniform` and `order1`, both parsed from the
ANCHORS line (`runs.py:75-76`). Read them as follows:

- **`uniform` tracks the vocabulary, not the corpus** — it is a uniform distribution over the
  softmax width converted to bits/byte, so it moves with VMAX and with how much of the width was
  actually minted.
- **`order1` is a bigram fitted on train and scored on that run's own held-out slice** (`aac17f7`).
  It is the closest thing to a corpus fingerprint in the file, but it is **not exact**: it also moves
  with the held-out slice, which differs between runs — and before `0f96784` (**E10**) changing VMAX
  re-rolled the RNG and therefore the stream itself.

## What this file does not establish

- **No causal claim.** Every row records what was observed under stated conditions. Where a commit
  offers a mechanism, the mechanism is the commit's, quoted, not this file's.
- **n is mostly 1.** The only 3-seed results in the record are the population 2x2 (`cc0a377`), the
  seed floor and `nogrow` (`451459d`), `rampfrom2048` (`e9f2e58`), `ep18_big` (`bf53d40`), and the
  chain-credit toy (`7e9612d`). Everything else in `runs.csv` is a single run.
- **The seed floor is the binding constraint.** `33a9299` measured 1.227 b/B across four runs of one
  nominally identical arm; `5f4f117` documented 1.594 b/B between two runs differing only in whether
  checkpointing was on. Arm B's 0.080 spread (`cc0a377`) is the first configuration in the record
  stable enough for a 0.1 b/B difference to mean anything — and `a5cc7ea` then established that arm
  B is not reproducible at HEAD.
- **`runs/` holds nothing newer than the `equiv` pair.** Every GPU result from 2026-08-10 onward
  exists only in commit messages and `runs.csv`. This file is the index to the former.
